Project 05 • Automation

Semester Calendar Automation

A recurring administrative problem evolved from a personal AppleScript into a tested, Python-powered macOS application—with a browser-based JavaScript version planned next.

Project evolution

Version 1 • Legacy

AppleScript workflow

Read timetable data from Excel or Numbers, created class and teacher calendars in Calendar.app, and used a separate export step to produce shareable ICS files.

Established workflow

Version 2 • Current

Python + native macOS app

Challenge

At the beginning of each semester, teaching schedules arrive in spreadsheet form. Manually entering every class, weekday, start time, room, and recurrence into a calendar is slow and creates opportunities for transcription errors. The original AppleScript solved the immediate problem but depended on several Mac applications and had grown difficult to maintain.

Current solution

I replaced the multi-application process with Timetable to ICS, a double-clickable macOS application. A native Swift interface guides the user through the workflow while a Python conversion engine reads the Excel workbook and creates standards-compliant calendar files in the background.

Verified end-to-end result

Using a supplied semester workbook, the current app produced 28 class files, six teacher files, 84 class event series, and 84 teacher event series with zero validation warnings. All 168 event copies had distinct identifiers, preventing calendar applications from collapsing class and teacher copies into one event.

What improved in the macOS app

  • Direct Excel input: the app reads XLSX or XLSM workbooks without requiring Excel or Numbers to be open.
  • No automatic calendar changes: it creates files for review and import rather than deleting or replacing Calendar.app calendars.
  • Validation before export: malformed dates, incomplete timetable cells, missing teacher matches, and invalid semester ranges are reported before files are created.
  • Review screen: users confirm the worksheet, dates, counts, time zone, aliases, and warnings before export.
  • Safer output: every run creates a new timestamped folder, so earlier exports are not overwritten.
  • Portable calendar files: recurring ICS events work with Apple Calendar, Google Calendar, Outlook, and many mobile calendar applications.
  • Offline operation: the conversion engine uses Python’s standard library and does not require an internet connection or additional Python packages.

Validation

The current Python conversion engine passes 14 automated tests covering timetable parsing, merged headings, date validation, teacher aliases, recurrence, calendar formatting, unique event identifiers, error handling, and safe output behavior. The macOS application is also built and signed locally as a native app bundle.

Next version: JavaScript web app

The next planned version will move the workflow into a web browser. The aim is to preserve the current validation and ICS-generation logic while making the tool easier to use on Windows, macOS, and other modern systems. The intended workflow is to select a timetable locally, review the proposed calendars, and download the generated files.

This remains a roadmap item, not a completed product. Privacy will remain a design requirement: the preferred approach is browser-side processing so institutional timetable data does not need to be uploaded to a server.

Reach and limits

The earlier workflow was used for semester calendar setup and its generated files were imported by several colleagues. The current macOS app has passed automated and end-to-end testing against a real timetable structure, but broader staff adoption and the JavaScript web version have not yet been measured or completed.

Privacy by design

The public example is fictional. Real teacher names, class assignments, rooms, dates, email addresses, workbooks, and calendar files remain private. The portfolio does not provide downloadable institutional schedules.

Lesson learned

Automation improves in stages. First, solve the recurring problem. Then separate the transformation from the applications around it, add validation and review, and finally make the workflow accessible to more users.
